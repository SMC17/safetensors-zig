# Fixtures

Every benchmark claim in this repository is bounded by the test fixtures used to produce it. The fixtures are committed and dated. A reimplementation that does not use the same fixtures is not refuting the claims here; it is running a different experiment.

## `tests/fixtures/llama-shape/`

39-tensor synthetic safetensors blob, Llama-3.2-1B-Instruct topology (embedding + 16 decoder layers × 7 tensors-per-layer + final-norm + lm_head). 33 MB. Generated by `tests/gen_fixture.py` from Python stdlib only — no torch, no `safetensors` package, no HF tooling.

Llama-shape, not random. The parse hot path is JSON metadata: tensor count, encoded shape arrays, per-tensor `data_offsets`. Random-shape blobs do not match the production profile because they do not have the regular `model.layers.{N}.self_attn.{q,k,v,o}_proj.weight` naming and repeated-shape patterns. The fixture is calibration-bound to the workload (LLM inference weight load) the parser was built for.

1B-class, not 7B+. Parse cost scales linearly in tensor count; numbers extrapolate to 70-layer 70B. 1B keeps the fixture small enough to commit and round-trip on every CI run.

Curation choices, embedded:

- Random float32 *bytes*; real-Llama tensor *shapes*. Parse is metadata-only — the bytes are random because they don't matter, the shapes are real because they do.
- `__metadata__` map present with `format: "pt"` and synthesised `total_size`. The path that handles metadata is harder than the path that doesn't. The bench reflects the worst case.
- `data_offsets` contiguous, non-overlapping. The parser handles non-contiguous; the bench fixture is contiguous because the common case is contiguous.
- Float32 across all tensors. Real Llama is BF16. Parse is dtype-agnostic. Float32 keeps the generator stdlib-only.

## `tests/test_realmodel.zig`

Integration test against TinyLlama-1.1B-Chat-v1.0 canonical `model.safetensors` (2.2 GB, 201 tensors, BF16). Verifies all tensors parse, BF16 dtype path works, `total_size` matches, naming convention holds.

Synthetic fixtures test the parse path. The real-model fixture tests the *acceptance envelope* — that the canonical HF-published file does not have a quirk we did not anticipate (unusual escape sequence in a tensor name, `__metadata__` field we do not handle).

The real-model fixture is gated behind a download step. `tests/fixtures/tinyllama-real/` is gitignored; CI bootstraps from HuggingFace Hub.

This is *not* a guarantee that all HF safetensors files parse. It is a guarantee that the canonical TinyLlama-1.1B-Chat-v1.0 file parses and that the IDs and shapes match. Community fine-tunes with custom metadata may surface bugs the canonical fixture does not.

## Why reproducibility binds to the fixture

A clean-room reimplementation in another language can claim "N× faster than HF Rust upstream" only by running the same comparison on the same fixtures. The Llama-shape fixture is committed verbatim. `tests/gen_fixture.py` is deterministic — seeded RNG. A port that reports different speedup numbers on different fixtures is running a different experiment.

The fixture is curated to surface the costs we optimised against. Random-shape blobs, single-tensor toy files, pathological multi-file shards — each understates or overstates the comparison depending on which part of the parser they exercise. The Llama-shape fixture is the calibration we committed to.
