# Test fixtures — what they are, why they bound the claims

Every benchmark claim in this repository is bounded by the test
fixtures used to produce it. The fixtures are part of the published
contribution, not incidental scaffolding. Without them, the "5x faster
than HF Rust upstream" claim is unanchored — a clean-room reimplementation
that doesn't use the same fixtures cannot reproduce the comparison.

## Fixture inventory

### `tests/fixtures/llama-shape/`

**What:** A 39-tensor synthetic safetensors blob mirroring the
**Llama-3.2-1B-Instruct** tensor topology (embedding + 16 decoder
layers × 7 tensors-per-layer + final-norm + lm_head). Total on-disk
size ≈ 33 MB. Generated by `tests/gen_fixture.py` using only Python
stdlib (no torch, no `safetensors` package, no HF tooling).

**Why this shape, not random:** the parse-hot-path bench claims are
about *header parsing* — the JSON dtype/shape/offsets metadata block,
not the raw tensor bytes. The number of entries in the header,
their string-encoded shape arrays, and the per-tensor `data_offsets`
entries dominate parse wall-time. Random-shape fixtures don't match
this profile because they don't have the regular `model.layers.{N}.self_attn.{q,k,v,o}_proj.weight`
naming + repeated-shape patterns that real Llama-family models have.
The Llama-shape fixture is calibration-bound to the real workload
(LLM inference weight load) the parser was built for.

**Why 1B-class, not 7B+:** the parse hot path scales linearly in
tensor count; the bench numbers extrapolate proportionally to
70-layer 70B Llama. Using a 1B-class shape keeps the fixture small
enough to commit, version-control, and round-trip on every CI run
without bandwidth or storage friction.

**Taste decisions embedded in the fixture:**

1. **Random float32 tensor *bytes* but real-Llama tensor *shapes*.**
   We care about parse, not data correctness, so the bytes are random;
   we care about realistic header complexity, so the shapes are real.
2. **`__metadata__` map present with `format: "pt"` and a synthesised
   `total_size`.** Some HF safetensors files omit `__metadata__`; ours
   includes it because the parse path that handles it is harder than
   the path that doesn't, and we want the bench to reflect the worst
   case.
3. **`data_offsets` are contiguous and non-overlapping.** Real
   safetensors files are mostly contiguous; pathological non-contiguous
   layouts exist (when weights are sharded across files and merged) but
   are out-of-scope for the v0.3 bench. The parser handles non-contiguous
   layouts; the bench fixture is contiguous because that's the common case.
4. **Float32 dtype across all tensors.** Real Llama uses BF16. The
   parse path is dtype-agnostic; the choice of float32 keeps the fixture
   generator stdlib-only (no `bfloat16` numpy dependency). The bench
   timing is dtype-invariant because parse is metadata-only.

### `tests/test_realmodel.zig`

**What:** Integration test that round-trips through a real
HuggingFace-published safetensors file (TinyLlama-1.1B-Chat-v1.0
canonical `model.safetensors`, 2.2 GB). Verifies that all 201 tensors
parse cleanly + the BF16 dtype path + the actual `total_size`
metadata value + the canonical naming convention.

**Why real-model integration, not just synthetic:** synthetic fixtures
test the parse path; the real-model fixture tests the *acceptance
envelope*. If a real HF-published file has a quirk we didn't anticipate
(unusual escape sequence in a tensor name, `__metadata__` field we
don't handle), the synthetic fixture won't surface it. The real-model
test is gated behind a fixture-download step (`tests/fixtures/tinyllama-real/`
is gitignored; CI bootstraps it from HuggingFace Hub).

**What this fixture is NOT:** it is not a guarantee that *all* HF
safetensors files parse. It's a guarantee that the canonical
TinyLlama-1.1B-Chat-v1.0 file parses + the canonical IDs and shapes
match. Files from non-standard publishers (community fine-tunes with
custom metadata, etc.) may surface bugs the canonical fixture doesn't.

## Why the fixtures matter for reproducibility

A clean-room reimplementation of `safetensors-zig` in another
language can claim "Nx faster than HF Rust upstream" only by running
the same comparison on the same fixtures. The Llama-shape fixture
is committed verbatim; `tests/gen_fixture.py` is deterministic
(seeded RNG). Any port that uses *different* fixtures and reports
*different* speedup numbers is not refuting our claims — it's
running a different experiment.

This is intentional. The fixture is curated to surface the costs we
optimised against. Other fixtures (random-shape blobs, single-tensor
toy files, pathological multi-file shards) would either understate
or overstate the comparison depending on which part of the parser
they exercise. The Llama-shape fixture is the calibration we
publicly committed to.

copyrighted material). It is included under the same AGPL-3.0-or-later

downloaded at test time).

If you reproduce these benchmarks, cite the fixture: `safetensors-zig
tests/fixtures/llama-shape/ (39 tensors, Llama-3.2-1B-Instruct shape
profile, deterministic synthetic; bench v0.3)`.
